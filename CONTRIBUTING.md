# Contributing to Royalpuskar projects

Thank you for helping make these research prototypes more reliable. Start with the [project catalogue](PORTFOLIO.md) and choose one repository with a focused technical question.

## A useful first contribution

1. Read the project's README, limitations and license.
2. Reproduce its synthetic example and documented tests on an authorized local machine.
3. Identify a specific behavior, accessibility issue, test gap or documentation error.
4. Open an issue in that repository with the tested commit, expected result, actual result and minimal synthetic reproduction.
5. If proposing a fix, use a branch, keep the change focused, add a regression test and describe what was actually executed.
6. Request review and address feedback; do not self-certify security or pressure maintainers to merge.

Good contributions include boundary cases in Token Lifecycle Lab, graph fixture coverage in Trust Path Explorer, false-positive analysis in Social Mind AI and accessible keyboard navigation in local demos. Coordinate competition-related work with the entrant and respect event rules.

## Security and collaboration

Use fictional examples and authorized inputs. Never post real credentials, private messages or personal records in issues. Follow the relevant project's SECURITY.md when provided; avoid public disclosure of unresolved sensitive findings. Respect applicable licenses, attribute other contributors accurately and disclose AI assistance when required. No artificial stars, fabricated co-authorship or empty PRs for badges.

The maintainer reviews contributions on their merits. No promise of an award, merge, endorsement or professional certification is made.
